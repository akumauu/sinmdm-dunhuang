# 敦煌舞三维动作生成系统 - 技术开发文档

**版本**: v2.0  
**最后更新**: 2026-02-28

---

## 1. 系统概述

本系统基于 **SinMDM (Single Motion Diffusion Model)** 框架，实现了一条完整的 "敦煌舞 BVH 数据 → 预处理 → 扩散模型训练 → 动作生成 → 后处理 → 标准 BVH 导出" 技术路径。系统结合了 **扩散模型 (Diffusion Model)** 与 **QnA (Query-and-Attention) 架构**，针对中国传统敦煌舞蹈的复杂姿态进行了深度优化，并提供了基于 Gradio 的桌面端交互界面。

### 1.1 技术路线

```
敦煌舞 BVH 数据
    ↓
数据处理模块 (解析 → 预处理 → 验证)
    ↓
SinMDM 生成引擎 (QnA + ExponentialLR 训练 → 扩散推理)
    ↓
后处理模块 (SavGol 平滑 → 关节约束 → 根节点稳定)
    ↓
输出层 (标准 BVH 导出 + 骨架动画视频)
    ↕
Gradio 桌面端界面 (数据管理 / 模型训练 / 生成预览 / 导出设置)
```

## 2. 核心技术框架

### 2.1 扩散模型 (Diffusion Model)

本系统采用高斯扩散过程作为核心生成算法：
- **前向过程 (Forward Process)**：在原始动作数据中逐步加入噪声，直到其变成纯高斯噪声。
- **反向过程 (Reverse Process)**：训练神经网络学习如何根据当前加噪状态和步数 $t$ 预测并去除噪声，从随机噪声中恢复出流畅的动作。
- **单序列学习**：SinMDM 的核心优势在于仅需单条动作序列即可学习其内部运动模体 (Motif)，特别适合敦煌舞这种数据稀缺场景。

### 2.2 QnA Net 架构

不同于传统的 Transformer，本系统采用了 **QnA (Query-and-Attention)** 架构：
- **分层特征提取**：通过类似卷积的局部注意力机制，更有效地捕捉人体骨骼的时空局部特征。
- **计算效率**：在处理长序列动作数据时相比标准 Attention 具有更高的效率和更好的泛化能力。

## 3. 系统模块详解

### 📁 3.1 数据处理模块 (`dunhuang_dance_gen/data/`)

| 组件 | 文件 | 功能 |
|------|------|------|
| BVH 解析器 | `bvh_parser.py` | 解析 BVH 骨架层级与动作数据，输出 `BVHData` 结构体 |
| 预处理器 | `preprocess.py` | 帧率重采样(30fps)、异常帧检测修复、SavGol 平滑、尺度归一化 |
| 数据验证器 | `validator.py` | NaN/Inf 检测、速度/旋转异常报警、SinMDM 兼容性检查、质量评分 |

- **BVH 解析**：自动解析骨骼层级，将关节旋转角度转换为 **6D 旋转表示**，相比四元数或欧拉角连续性更强。
- **归一化处理**：通过减均值和缩放保证输入数据分布在网络易于学习的区间。
- **数据验证**：自动检测数据质量，输出 0-100 分的质量评分。

### 🧠 3.2 模型实现模块 (`models/` & `dunhuang_dance_gen/models/`)

| 组件 | 文件 | 功能 |
|------|------|------|
| QnA MDM | `models/` | 主模型，QnA Net + 时间步编码 + 动态维度投影 |
| SinMDM 封装 | `sinmdm_wrapper.py` | Python API 封装，支持 `train()` / `generate()` / 命令生成 |

- **`QnAMDM` 类**：根据输入动作的关节数和特征维度动态调整投影层，实现了对不同骨骼定义（如 198 维敦煌舞 vs 263 维 HumanML3D）的完美兼容。
- **`SinMDMWrapper` 类**：封装了训练和推理的 subprocess 调用，支持参数化配置。

### ⚡ 3.3 后处理模块 (`dunhuang_dance_gen/postprocess/`)

| 组件 | 文件 | 功能 |
|------|------|------|
| 动作平滑器 | `smooth.py` | Savitzky-Golay / 高斯滤波、速度突变修复、自适应平滑 |
| 物理约束 | `constraints.py` | 关节角度限位(软/硬)、足部滑动抑制、根节点稳定、地面穿透修正 |
| 集成管线 | `pipeline.py` | 一键执行完整后处理链，输出处理前后对比统计 |

**后处理管线执行顺序：**
1. 速度突变修正（阈值检测 + 线性插值）
2. Savitzky-Golay 平滑滤波（可配置窗口/阶数）
3. 关节角度限位（肘/膝/髋/脊柱，软 tanh 压缩）
4. 根节点运动稳定（XZ 平面 + Y 旋转平滑）
5. 地面穿透修正（确保 Y ≥ ground_level）

### 📊 3.4 评估模块 (`dunhuang_dance_gen/evaluate/`)

| 指标 | 说明 | 论文章节 |
|------|------|---------|
| 帧间平滑度 | 角速度/角加速度的均值与标准差 | 第6章 |
| 关节越界率 | 肘/膝/髋/脊柱超出物理范围的比例 | 第6章 |
| 根节点抖动 | 根节点加速度均值 | 第6章 |
| 分布相似性 | 生成与参考动作的均值/方差距离 | 第6章 |

支持批量评估 + 自动生成 Markdown 汇总表格。

### 📤 3.5 导出模块 (`dunhuang_dance_gen/export/`)

- **BVH 标准导出**：ROOT 6 通道 (位置+旋转)，JOINT 3 通道 (旋转)，ZXY 旋转序。
- **Euler Unwrap**：消除帧间旋转跳变（±360° 归一化）。
- **69 列断言**：确保 22 关节 × (3+旋转通道) 格式正确。

### 🖥️ 3.6 桌面端界面 (`app.py`)

基于 **Gradio** 构建的 Web 界面，包含 4 个功能 Tab：

| Tab | 功能 |
|-----|------|
| 📁 数据管理 | BVH 文件选择/上传 → 骨架信息展示 → 3D 预览 |
| 🧠 模型训练 | 超参数配置（架构/步数/学习率/保存间隔）→ 命令生成 |
| 🎬 生成预览 | 模型选择 → 参数控制（时长/数量/种子）→ MP4 预览 |
| 📤 后处理与导出 | 平滑/约束配置 → 一键处理 → 评估报告 → BVH 下载 |

### 🔬 3.7 可视化模块 (`dunhuang_dance_gen/visualize/`)

- **骨架渲染**：3D 关节点 + 骨骼连线，支持标签显示。
- **动画播放**：FuncAnimation 驱动，可保存为 MP4/GIF。
- **对比视图**：并排展示原始 vs 生成动作。
- **轨迹绘制**：根节点运动轨迹可视化。

## 4. 关键技术修复与优化

在本项目开发过程中，进行了以下核心修复与优化：

1. **动态维度匹配**：解决了原框架硬编码 263 维导致的维度冲突，支持 198 维敦煌舞数据。
2. **BVH 直传模式**：实现了单文件即入即练，避开了繁琐的多步预处理。
3. **BVH 导出标准化**：将非 Root 关节改为 3 通道旋转（ZXY），修复了 Blender 导入时的骨架错位问题。
4. **渲染稳定性**：通过 Auto-Framing 解决了生成视频白屏或角色在视野外的问题。
5. **后处理管线集成**：新增完整的后处理链（平滑→约束→稳定→导出），支持参数配置和前后对比。
6. **量化评估体系**：建立了帧间平滑度、关节越界率、根节点抖动、分布相似性 4 类客观指标。
7. **桌面端 GUI**：基于 Gradio 实现了 4 Tab 交互界面，覆盖完整数据→训练→生成→导出流程。

## 8. 使用建议（针对毕设评估）

- **训练步数**：对于单段舞蹈，建议步数在 10,000-20,000 左右为宜，过高可能导致过拟合。
- **标准化检查**：导出的 BVH 应为 69 列（22 关节），可直接在 Blender 中驱动标准骨架。
- **后处理**：生成后建议使用 SavGol 平滑（window=5）+ 关节限位，可显著改善运动质量。
- **评估**：使用 `evaluate/metrics.py` 自动生成量化指标表格，可直接用于论文第 6 章。
- **界面截图**：启动 `python app.py`，截取各 Tab 界面用于论文系统实现章节。
